# Workflow: Validation / Audit (V0–V1)

> 门禁：`gates/integration.yaml`（G-INTEG）· 原则：**不采信自述、只读复跑、抽样验证**
> 输入：全部生成物 + 报告 + 门禁清单；输出：验收报告 + 审计报告 + 风险登记建议。

## 1. 阶段表

| 阶段 | 输入 | 动作 | 输出 | 证据 / 门禁 |
|---|---|---|---|---|
| V0 独立验收 | 产物、门禁 | 只读复跑关键命令；抽样 | `VERIFY_REPORT.md` | 7/7 + 增量 10/10（本项目） |
| V1 逐条审计 | PRD、流水线、证据 | 逐条 PASS/PARTIAL/GAP/SUPERSEDED/N-A | `AUDIT_{PRD,PIPELINE,ENV}.md` | 185 条 / 146 项 / 15 版本 |

## 2. V0 抽样规则

- 每个数字至少抽 1 个复跑（机械/ERC/DRC/DFM/固件/仿真各抽 1）。
- 每个报告里的 `0` 必须打开原始报告确认（例：`DRC_2l.rpt` 的 "0 DRC violations"）。
- 每个"全部通过"必须追问"哪些没测"（→ 写入 §未测项）。
- 元验收：验收脚本是否只读、是否可一条命令复跑、是否有断言。

## 3. V1 判定口径

| 判定 | 含义 |
|---|---|
| PASS | 仓库有实现/产物，且审计独立复核 |
| PARTIAL | 部分实现、数值/描述不一致，或只有数字证据缺实物 |
| GAP | 缺失/未关闭/方向不符 |
| SUPERSEDED | 被后续用户变更覆盖（不计缺陷） |
| N/A | 当前阶段不适用（Solar/量产等） |

## 4. 复用清单

- [ ] 验收报告带基线 commit + 时间戳 + 工具版本。
- [ ] 抽样记录写清"复跑了哪条、结果如何"。
- [ ] 未测项/不能证明的边界单列成章。
- [ ] 发现项编号/定级/整改建议/责任方。
- [ ] 历史文档加 OBSOLETE 横幅，不删。
- [ ] 二轮复验保留修复前/后记录。

## 5. 已知失败模式

| 现象 | 根因 | 预防 |
|---|---|---|
| 只看 README/自述 | 图省事 | 只读复跑 + 抽样 |
| 只看测试总数不看阈值 | 计数代替质量 | 每条看判据 |
| 把历史证据当当前证据 | 时间戳没看 | 校验证据晚于源改动 |
| 发现项悄悄降级 | 怕报告难看 | 风险登记保留 + 编号 |
| "全部通过"没有边界 | 结论化 | 写 PASS/PARTIAL/GAP + 未测项 |

## 6. 边界

- validation 不修代码（除非明确授权），只报告与给整改建议。
- 审计数字是当时快照；后续变更必须加注记，不回头改旧结论。
