# Workflow: Integration / Lead (I0–I1)

> 门禁：`gates/integration.yaml`（G-INTEG）· 职责：拆任务、控写作用域、集成、收口、交接。

## 1. 阶段表

| 阶段 | 输入 | 动作 | 输出 | 证据 / 门禁 |
|---|---|---|---|---|
| I0 任务板 | 计划、角色 | 拆任务；owner/写作用域/依赖 | `TASK_BOARD.md` | 无重叠写作用域 |
| I1 集成收口 | 各域产物、验收/审计 | 跨层一致性 + 最终 diff + 测试 + HANDOFF | HANDOFF/README/commit | G-INTEG 全绿 |

## 2. 任务拆解规则

- 每个任务：目标、输入、输出、验收标准、owner、写作用域、依赖。
- 写作用域是 **advisory 不是锁**；重叠时 Lead 显式排序。
- 需要多步依赖时用依赖边，不用口头约定。
- 每个 teammate 的 prompt 必须**自包含**：路径 + 规范 + 验收 + 禁止事项。

## 3. 集成检查（每轮）

1. **跨层一致性**：BOM ↔ 原理图 ↔ PCB ↔ pos ↔ 装配图 ↔ 固件引脚 ↔ docs。
2. **变更传播**：任一源改动 → 列出必须重跑的生成链（机械/电子/固件/渲染/提交包）。
3. **时间戳顺序**：报告/图片/产物晚于源文件。
4. **全链路复跑**：至少跑各域"一条命令" + 项目验收脚本。
5. **最终 diff 审阅**：Lead 亲自看差异，不只看 teammate 自述。
6. **独立验收**：validation 只读复跑；GAP 登记。

## 4. 收口清单

- [ ] `docs/HANDOFF.md`：状态 / 根因 / 命令 / 剩余项 / 红线。
- [ ] `README.md`：结果一览 + 证据入口 + 用户待办。
- [ ] `TASK_BOARD.md`：任务状态 + 证据。
- [ ] commit 信息写清原因与证据（不是 "update"）。
- [ ] 向用户报告：达成/未达成 + 需要用户动手的事项。

## 5. 已知失败模式

| 现象 | 根因 | 预防 |
|---|---|---|
| 两个 Agent 写同一文件 | 写作用域没隔离 | 任务板登记 + Lead 排序 |
| 转述子 Agent "通过" | 没复核 | Lead 看证据/复跑 |
| 跨域不一致 | 只改一处 | 一致性表 + 全链路重跑 |
| 交接后无法冷启动 | HANDOFF 只写结论 | 写命令/路径/根因/剩余项 |
| 文档互相矛盾 | 多处手写同一数字 | 单一来源 + 生成物引用 |

## 6. 边界

- Lead 不替 product 编需求、不替 validation 下结论。
- 用户侧事项（采购/装配/标定/打样/授权）只准备清单与记录表。
