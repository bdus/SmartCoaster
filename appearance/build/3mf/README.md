## Placement / fit (from `appearance/build/shell/shell.json` + Kromacut `manifest.json`)

| | round (dog) | square (elf) |
|---|---|---|
| shell | LUMEN Ø110 × 17 | square_v1 100×100 × 18 |
| print | Ø86.4 × 1.20 mm, 6 filaments | Ø86.4 × 1.40 mm, 7 filaments |
| pocket | Ø86.0 mm, floor z = 15.75 | Ø86.0 mm, floor z = 16.55 |
| print transform | translate (0, 0, 15.75) mm, no rotation | translate (0, 0, 16.55) mm, no rotation |
| print top | z = 16.95 → **0.05 mm below rim 17.00** | z = 17.95 → **0.05 mm below rim 18.00** |
| radial fit | 0.200 mm nominal, **0.288 mm max** (Ø86.4 nominal + 0.088 mm pixel-staircase corners) | same |
| world z of filaments | 15.75…16.95 | 16.55…17.95 |

Shell and print are **separate objects / separate collections** in the .blend and separate
objects in the 3MF; nothing is boolean-merged. Bambu Studio fuses them at slice time.

**Triangle preservation:** each per-filament component exports the filament's complete STL
triangle set (vertex welding only, no triangle de-duplication). The coincident
opposite-winding caps between abutting layout parts of the same filament are intentional
interface faces that keep each filament solid closed — they must not be deduped.

## Bambu Studio note

The package is plain 3MF core spec; it contains **no Bambu-proprietary
`Metadata/model_settings.config`**. Open it in Bambu Studio, set the printer/plate, then
assign each of the print filament components (and the shell/plate if printed in different
filaments) to an AMS slot — colours are already the Kromacut palette so "use current
filament colours" usually maps them 1:1. If you want the original Bambu object/part
settings, the print-only reference exports `dog_kromacut.3mf` / `elf_kromacut.3mf` already
carry Kromacut's Bambu metadata. Fusing the print into the shell happens at slice time.
